# 채용공고 직무 분류

수집 공고의 `desiredJob`을 `DesiredJob`의 개발 직무 10종으로 분류한다.
산업군(B2C, 핀테크 등)이나 회사명으로 직무를 추측하지 않는다.

- 제목에서 명시적인 직무를 찾는다. 제목에 없을 때만 `job_category`를 사용한다.
- 제목에 여러 직무가 있으면 미분류(null)로 둔다. 명시적 풀스택과 프론트/백엔드 병기는 FULLSTACK으로 묶는다.
- 본문 기술 나열은 직무의 근거로 사용하지 않는다.
- 수집 내용 해시가 같아도 직무를 다시 계산한다.
- 신규 분류는 기존의 직무별 부족 기술 조회 및 신규 공고 알림 조건에 전달된다.

## 기존 데이터 보정

관리자 토큰으로 `POST /api/admin/crawling/classify-jobs?afterId=0`을 호출한다.
응답의 `nextAfterId`를 다음 요청의 `afterId`로 사용한다. `hasMore=false`면 종료한다.
`hasMore=true`는 배치가 가득 찼다는 뜻이며 마지막에 빈 배치를 한 번 더 받을 수 있다.

한 요청에서 미분류 공고를 ID 오름차순으로 최대 200건 처리한다.
`scanned`, `classified`, `unclassified`는 해당 요청의 처리 건수다.
이미 분류된 공고는 유지하며 과거 공고 알림은 생성하지 않는다. DB 스키마 변경은 필요 없다.

분류 규칙을 확장한 후에는 `afterId=0`부터 다시 실행하면 남은 미분류 공고를 재평가한다.
운영 실행은 응답 건수를 확인하며 진행한다. 이 변경 자체가 기존 운영 데이터를 수정하지는 않는다.
